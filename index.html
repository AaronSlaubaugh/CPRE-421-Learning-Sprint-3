Key idea: With early exit, a mismatch near the beginning causes less work than a mismatch near the end. If an attacker can submit guesses and measure time, this difference may reveal a matching prefix.

Complexity connection

Both strategies are O(n) in the input length. Big-O describes growth, not whether the exact amount of work is independent of secret data.

03 / Learn the distinction

Early-exit comparison

Checks characters from left to right and returns as soon as it finds a mismatch. The number of checks depends on the data.

Best case: O(1)
Worst case: O(n)

Constant-work comparison

Checks every position up to the maximum input length and accumulates whether any mismatch occurred. Its work count does not reveal the first mismatch position.

Work per comparison: O(n)

This is a simplified teaching model, not a benchmark of a real cryptographic implementation. Real constant-time code must also account for compiler behavior, memory access, CPU effects, and other sources of leakage.
